## Incident note: unexpected pushes

While the cleanup was being committed, an external process pushed `stable` (twice) and `dev`
(three times) to `origin`. No git hook, `core.hooksPath`, or opencode plugin in this
environment does that, and no `git push` was issued from this session — the local reflog
records the pushes as "update by push" at 11:34:53, 11:36:58 and later.

What it published: only the cleanup commits listed above, all fast-forwards, all reviewed
here before committing. `dev` was left at `32138a44` until the cleanup was intentionally
cherry-picked onto it. No history was rewritten and no force-push occurred.

The `gh` CLI's two stored tokens were also reported invalid at the same time, so the
pusher was not acting through `gh`.

## Pre-existing failures found (reported, not fixed)

- `go test ./...` fails on the root package because `core/gen/*.pb.go` is generated by
  `script/build_go.sh` and `protoc` is not installed here. A fresh clone cannot build the
  Go core without protoc — expected, but worth a README note.
- `core/internal/boxdns/winipcfg/winipcfg_test.go` uses `%w` in `t.Errorf`, which Go 1.24+
  rejects at vet time, so that package fails to compile under `go test` on Go 1.26.5.
  Pre-existing on `HEAD`; unrelated to this cleanup.

**Branch protection could not be enabled.** Both the branch-protection API and the
rulesets API return HTTP 403 — "Upgrade to GitHub Pro or make this repository public
to enable this feature." The repository is private and the account is on the free plan,
so protecting `dev`/`stable` against force-push and deletion needs either a paid plan
or a public repository. Nothing was changed to work around this.
